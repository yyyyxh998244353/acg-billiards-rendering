# 动态路径追踪 CPU 实验记录

基线提交为 `39d0371`。本记录覆盖 WorkMac 上的静帧精度实验、CPU 渲染器优化和 Linux CPU 集群复验。计时中的「整帧」包含 PPM 写盘，从一帧的场景准备开始，到写盘完成为止。

## 保留的实现

| 区域 | 实现 |
|---|---|
| 房间求交 | CPU 使用预计算的房间 BVH 和室内子树。ARM64 以 NEON 检查紧凑节点包围盒，符合几何条件的顶视主射线直接检查台布与球体。 |
| 球体与阴影 | 线扫、重建和 refit 保留原球编号和严格命中区间。ARM64 的球体候选筛选后仍调用原球面求交。阴影查询省略法线。点光源的射线位于经几何验证的台布中央区域时只查球体。 |
| 着色和像素输出 | 同一命中的 GGX 样本复用出射侧项。每行预计算随机种子的行贡献。Apple ARM64 在能确定 8 位输出的亮度区间查表，接近量化边界的值沿用原公式。 |
| 可选点光源缓存 | `ACG_INTERPOLATE` 在单曝光姿态的帧上构建软漫反射接收面指引。缓存由台布位置、球体接触区域和网格一致性检测约束。需要精确阴影的区域回退到射线查询。 |

## WorkMac CPU

Apple M5 Pro 上，预览构建使用 `-DACG_MAX_HITS=2 -DACG_AREA_SAMPLES=1`。回放选用 14 线程、`OMP_WAIT_POLICY=PASSIVE`、`ACG_BVH=scan` 和 `guided,1`。最末一次重建与基线的四组完整路径 PPM 字节一致。720p、1 spp 预览的 20 帧逐帧 SHA‑256 一致，重建版 p95 为 17.94 ms，20 帧均在 33.33 ms 内完成。

Apple ARM64 的 sRGB 查表曾在本机工具链上覆盖 234,881,024 个表范围内的 `float32` 输入，输出与公式一致。在两轮 720p 预览对照中，配对整帧耗时下降 4.68% 和 3.36%。

对球体遮挡后立即结束阴影查询的最后一轮试验使用两段 720p、2 spp 回放。四轮逐帧 SHA‑256 一致，配对整帧耗时中位数分别增加 3.78%、增加 0.13%、减少 2.91%、增加 0.26%，所以撤回该候选。偏移原点和入射余弦复用、面积灯面求交跳过、正余弦多项式以及调度切换也完成了对照，现有回放收益不足以替换保留的构建。

### 水平分块调度

比较整行、256 像素和 512 像素三种任务粒度，均采用 OpenMP `guided,1`。固定种子的四组短测通过 PPM 字节对照。256 像素分块在 960×528、1 spp 短测中的预览和完整路径渲染耗时分别下降 3.90% 和 2.55%。

随后用 14 线程跑 720p 连续回放，覆盖开球前第 12–31 帧和散球段第 50–69 帧。预览为 1 spp，完整路径为 2 spp。两个片段各做两轮交替测量，使用训练未见的轨迹姿态和独立采样种子。所有逐帧 SHA‑256 一致。下表给出候选相对整行的配对整帧耗时降幅，正值表示更快。

| 片段 | 渲染路径 | 256 像素，两轮 | 512 像素，两轮 |
|---|---|---:|---:|
| 开球前 | 预览 | −1.53% / +2.61% | −0.91% / +0.16% |
| 开球前 | 完整 | −0.29% / +1.75% | −0.14% / +2.58% |
| 散球 | 预览 | +0.57% / +8.88% | +0.77% / +8.88% |
| 散球 | 完整 | +0.26% / +1.59% | +2.44% / +1.62% |

散球段预览的第二轮整行基线 p95 升至 21.95 ms，第一轮为 17.22 ms。考虑两段回放的中位数和尾延迟波动，本轮撤回水平分块试验。

## Linux CPU 集群

通过 Slurm 在 `i2` 上验证 x86‑64、GCC 14.3.1。完整路径规格为 320×176、2 spp，物理种子为 `42`，轨迹以 60 FPS 导出。验证帧为 30–32 和 60–62，每轮以相同的采样种子按交替次序运行，写出 PPM 后比较 SHA‑256。

| 对照 | 轮次 | 基线整帧中位数 | 候选整帧中位数 | 配对整帧耗时降幅 |
|---|---:|---:|---:|---:|
| 1 线程与 2 线程 | 1 | 252.64 ms | 189.83 ms | 24.89% |
| 1 线程与 2 线程 | 2 | 252.94 ms | 190.21 ms | 24.86% |
| 2 线程，GCC 默认优化与 PGO + LTO | 1 | 189.82 ms | 168.72 ms | 11.17% |
| 2 线程，GCC 默认优化与 PGO + LTO | 2 | 190.08 ms | 168.64 ms | 11.17% |

两项对照各自的六帧在四次运行中逐帧一致。PGO 训练使用不同的 7、44、75 帧，规格为 160×88、2 spp，采样种子为 `9347211`。基线使用 `-O3 -std=c++17 -fopenmp`。候选用 `-flto=2` 和 `-fprofile-generate` 构建训练程序，复用输出名并以 `-fprofile-use` 和 `-Werror=missing-profile` 构建计时程序。PGO 对照使用采样种子 `5537851`，表中数字是 PGO 与 LTO 的合并收益。

作业 `4034` 和 `4035` 均由 `sacct` 确认完成。每个作业占用 `i2` 上 2 个 CPU 核、768 MiB、10 秒，GPU 用量为 0。

### 分离 GCC PGO 和 LTO 的收益

作业 `4036` 在 `i2` 使用 2 个 CPU 核、768 MiB，运行 18 秒。源码 SHA‑256 与提交 `630db40` 一致。复用上面的六帧、分辨率和采样种子，用正序和反序各运行一轮。四种构建的六帧在八次回放中逐帧 SHA‑256 一致。

| 构建 | 两轮整帧中位数 | 相对默认构建的两轮配对耗时降幅 |
|---|---:|---:|
| `-O3 -fopenmp` | 191.20 / 190.45 ms | 0 / 0 |
| 仅 LTO | 192.67 / 192.77 ms | −1.47% / −1.28% |
| 仅 PGO | 170.98 / 171.25 ms | +10.11% / +10.19% |
| PGO + LTO | 168.56 / 168.51 ms | +11.35% / +11.42% |

仅 PGO 的构建使用相同训练输入和单线程训练设置。两轮中，PGO 提供了大部分收益，PGO + LTO 组合的整帧中位数最低。

## 核对范围

- 本机 ARM64 和集群 x86‑64 均编译运行 `check_soft_intervals.cpp`。72 组软阴影积分用例、遮挡、切线、掠射 BRDF、面积灯权重，以及球体、台布和灯具遮挡边界通过。
- 257×259、间距为 4 的网格跨过两个 OpenMP 分批边界。1 线程和 4 线程的输出坐标、值及各类像素计数一致，逐像素检查未发现重复写入。
- 逐帧哈希比较覆盖同一平台上的构建与线程配置。4K 精度结果的参考覆盖范围见上表。此次新集群运行的后端为 CPU。
